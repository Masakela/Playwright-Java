Testing an AI agent
like it's any other system under test.

A test framework that treats a non-deterministic AI agent as the system under test. It checks functional workflows, guardrails, data quality and task-success rate, and it also runs a classic SauceDemo UI regression suite. Everything runs end-to-end on a laptop or in CI with no external dependencies.

Two suites, one framework

AI agent workflows

AI as the system under test

A small reference agent service (agent-server/, Node with zero dependencies) is the system under test. Java tests call it over the API and drive its console in a real browser. They assert invariants rather than exact text.

  • Functional API + UI workflows
  • Guardrail refusals (prod deletes, secrets, moving funds)
  • Non-determinism: repeat runs, stable invariants
  • Eval harness with a task-success threshold
  • Data-quality checks on the agent's payload

UI regression

SauceDemo, Page Object Model

The original suite. Data-driven login and inventory tests against SauceDemo, using web-first assertions and auto-waiting. Each test gets its own isolated BrowserContext.

  • LoginPage, InventoryPage, BasePage
  • Excel-driven @DataProvider (logins.xlsx)
  • Chromium, Firefox and WebKit via -Dbrowser
  • Parallel methods with per-thread Playwright
  • No explicit waits anywhere

How the pieces fit

Everything hangs off one endpoint, POST /api/agent/run. The Java client sends a goal, and the agent returns a structured response that the evaluator, guardrails and data-quality checks score. A real browser then confirms the outcome in the agent's console.

Request

POST /api/agent/run
Content-Type: application/json

{
  "goal": "Create a user named John Doe
           with email john@example.com",
  "context": {}
}

Response (AgentResponse)

{
  "runId":   "run-…",        // never asserted
  "success": true,
  "refused": false,
  "message": "User created: john@example.com …",
  "actions": [{ "tool": "create_user", "status": "ok" }],
  "data":    { "userId": "u-0001",
               "email":  "john@example.com",
               "role":   "User" }
}

Offline and live, on purpose

Agent output is non-deterministic and a live agent isn't always available, so the suite is split into two groups. Offline tests keep the default build green. Live tests are the regression signal when the model or the prompt changes.

Offline · always runs

EvaluatorTestscoring logic
DataQualityTestpayload validation rules
GuardrailTestrefusal classification
AgentMockingTestUI against a mocked agent API (route.fulfill)

Live · group "live"

AgentApiUiWorkflowTestAPI creates a user, browser confirms it
AgentEvalHarnessTestgolden set ≥ eval.threshold
AgentNonDeterminismTestN repeats, invariants hold
AgentGuardrailLiveTestunsafe goals are refused

Quick start

Prerequisites: JDK 17+, Maven and Node 18+. No setup at all if you use Codespaces.

1

Install browsers (once)

mvn compile exec:java -e -D exec.mainClass=com.microsoft.playwright.CLI -D exec.args="install --with-deps"
2

UI regression + offline agent tests

mvn test
3

Full end-to-end, live agent included

./scripts/run-e2e.sh        # or .\scripts\run-e2e.ps1
4

Build the KPI dashboard locally

node scripts/kpi-report.js --junit target/surefire-reports --out kpis-out
